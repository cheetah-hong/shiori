# 교재 사진 OCR 테스트 기록

- 날짜: 2026-11-05 (KST), MacBook arm64 · macOS 26.3.1
- 교재: 시판 JLPT 단어장 N5–N3 (사용자 소유 교재). 사진 5장, 단어 59개
- **측정은 저장소에 포함하지 않은 교재 5쪽(59단어) 비공개 세트로 했습니다.** 판독 기록과 정답은 교재 본문이라
  로컬 전용 폴더(`$SHIORI_PRIVATE_DIR/textbook/vocab_n5n3/`, 기본 `<저장소>/.private`)에만 둡니다.
  저장소에는 같은 형식으로 지어낸 합성 세트(`packages/core/test/fixtures/synthetic/`, 6절)가 있습니다.
- OCR 엔진: **Apple Vision** (`VNRecognizeTextRequest`, accurate). 기기 안에서 처리하고 무료. iPhone과 같은 엔진
- 방법: 한 장을 **두 번 판독**합니다. 일본어 우선(`ja-JP,ko-KR`)과 한국어 우선(`ko-KR,ja-JP`)
  → 해석기(템플릿) → 보정기 → 정답 데이터와 비교
- 결론: **기기 OCR과 해석 규칙만으로 59개 중 52개가 줄 전체가 맞았습니다.** 틀린 7개 중 6개는 검토 화면에 표시되고,
  표시 없이 틀린 것은 1개입니다(한국어 판독이 뜻 한 글자를 잘못 읽음). 첫 버전에 Claude API는 필요 없습니다.

## 2. 교재 형식 두 가지

- **A형, 목록 (N5·N4, PART 1):** 한 줄 = 4자리 번호 + □□□ + 표제어 + (★) + 읽기 + [품사 배지] 뜻.
  읽기가 `あした/あす`처럼 여러 개일 수 있고, 가나 단어는 읽기 칸이 `–`입니다.
- **B형, 항목 (N3, PART 2):** 번호 □□□ 아래에 표제어 · 읽기 · [품사] 뜻이 한 줄 있고, 그 아래 후리가나 달린 예문과 번역,
  가끔 `[문형]` 설명과 `관련어` 상자가 있습니다.
- 공통: 위쪽에 `★ 표시 = …` 안내 문구, 아래쪽에 `PART … | DAY nn 제목 쪽번호` 꼬리말, 옆 페이지가 함께 찍힐 수 있습니다.

## 3. 해석·보정 규칙 (Dart `core` 구현의 기준)

기준 구현: `research/ocr/prototype/parse_eval.py`(같은 내용의 고정본 `tools/reference/parse_eval.py`).
Dart로 옮길 때 같은 데이터로 같은 점수가 나와야 합니다. 아래 예시는 합성 세트에서 가져왔습니다.

1. **형식 판별:** 번호 간격의 중앙값이 페이지 높이의 0.08보다 크면 B형, 아니면 A형.
2. **기준점(번호):** `^\d{4}`(I, l, | 는 1로 봄). 한 자리가 빠져 `121 ロロロ`처럼 읽혀도 체크박스가 붙어 있으면 기준점으로 받고,
   번호는 앞뒤 번호로 채웁니다.
3. **옆 페이지:** 기준점을 x 위치로 묶어 페이지를 나누고, 읽기 칸이 안 보이는 줄(잘린 옆 페이지)은 버립니다.
   B형은 가장 왼쪽 기준점보다 왼쪽에 있는 글자를 버립니다.
4. **A형 줄 찾기:** 번호만 믿지 않습니다. 읽기 칸의 가나 덩어리로도 줄을 찾고, 빠진 번호는 순서로 채웁니다(합성 `s010`의 0001).
5. **A형 기울기 보정:** 페이지마다 번호 → 단어 칸의 세로 차이(b)와 단어 → 읽기 칸의 기울기(s)를 중앙값으로 추정합니다.
   모든 덩어리를 `ref_y + s·(x − ref_x)`에 가장 가까운 줄에 배정합니다(허용 0.55 × 줄 간격). 기울어진 12·69쪽에서 필수입니다.
6. **칸 위치 (그 줄의 번호 x = ax 기준 상대 위치):** 표제어 `ax+0.02`–`ax+0.17`, ★ `< ax+0.23`, 읽기 `ax+0.195`–`ax+0.33`,
   뜻(한국어 판독) `ax+0.34`–`ax+0.56`. 오른쪽 DAY 탭과 위쪽 안내 문구(`표시 =`, `기출 단어`, `DAY`, `PART`, `mp3`)는 제외합니다.
7. **표제어 정리:** 앞의 번호와 체크박스 잡음(`□口ロコ■LDレ目問gG8` 연속)을 지웁니다. 체크박스 위치에서 시작하는 덩어리는
   앞의 잡음 글자를 모두 지웁니다(`口晴れ`→`晴れ`, `N天気`→`天気`).
8. **읽기:** 가나만 남기고 `/`로 나눕니다. `-`, `–`, `—`, `ー`, `一` 한 글자는 "읽기 없음"(가나 단어)으로 봅니다.
9. **뜻·품사:** 한국어 판독 덩어리를 x 순서로 잇고, 맨 앞의 품사 배지를 분리합니다.
   `명/동/형/い형/な형/부/접/감/연/조`이고, OCR 오인식 `통`→`동`, `몀`→`명`을 고치며 배지 뒤의 `.` `:`는 허용합니다.
10. **B형 예문:** 단어 줄 아래에서 높이가 읽기 줄의 0.75배 이상(후리가나 제외), 일본어 비율 0.85 이상, 한글 없음인 일본어 줄을 잇습니다.
    번역은 한국어 판독에서 한글 비율 0.5 이상인 줄입니다(앞에 붙은 일본어 잔여 토큰은 버림).
    `관련어`·`문형` 줄이 나오면 예문을 거기서 끊습니다.
11. **보정기 (차례로 적용, 바꿀 수 있는 블록):**
    - 헷갈리는 글자: 표제어 전체가 `ー - — + ニ ハ ロ`이면 `一 一 一 十 二 八 口`(읽기가 있을 때만).
    - 한자 사이의 가타카나 `タロエカニハ`는 `夕口工力二八`로 바꿉니다(`タ日`→`夕日`).
    - 읽기는 히라가나인데 표제어에 가타카나가 있으면, 끝에서부터 읽기와 맞는 글자는 히라가나로, 나머지는 한자 대응표로 바꿉니다
      (`光ル`→`光る`, `カ`→`力`).
    - 표시: `headword:missing`, `readings:missing`(한자가 있는데 읽기 없음), `meaning:missing`, `pos:missing`, `headword:corrected`.
12. **DAY·제목·쪽:** 한국어 판독 꼬리말 `DAY (\S{1,2}) 제목 쪽번호`. DAY 숫자 `이`는 `01`로 봅니다(0+1이 ㅇ+ㅣ로 보임).
    가운데 점(`•·・`)은 `·`로 통일합니다. 꼬리말이 없는 쪽은 위쪽의 `DAY` + 숫자 + 제목과 아래쪽 쪽번호 줄(`10 …`)을 씁니다.

## 4. 시도했지만 버린 방법
- **단어 칸만 잘라 크게 키워 다시 읽기:** 15개 중 8개로 오히려 나빠졌습니다. 단순한 한자는 따로 떨어지면 아예 무시됩니다.
- **회전 방향을 OCR 점수로 고르기:** 점수 차이가 거의 없어 판별이 안 됩니다(Vision이 돌아간 글자도 읽음).
  사진의 EXIF 회전 값을 쓰고, 앱에서는 문서 스캐너가 똑바로 세운 이미지를 받습니다.
  테스트 사진 중 2장은 EXIF 값 없이 옆으로 찍혀 있어 손으로 돌렸습니다.

## 5. 아직 확인하지 않은 것
- **Android ML Kit:** 이 측정 때는 Mac에서 돌릴 수 없어 측정하지 않았습니다. 이후 측정은 `research/ocr-android/README.md`.
- 사진 5장 기준입니다. 그림자·흐림·굽은 페이지가 심한 사진, 다른 DAY의 품사(`い형`, `な형`, `부`)는 더 모아야 합니다.
- 단순한 한자 표제어가 빠진 경우는 사전(JMdict) 블록이 들어가면 "읽기로 찾은 후보"를 보여 줄 수 있습니다(`docs/dictionary.md`).

## 6. 파일과 다시 돌리는 방법

| 경로 | 내용 |
|---|---|
| `research/ocr/prototype/parse_eval.py` | 해석기·보정기·채점기 기준 구현 |
| `research/ocr/tools/vision_ocr.swift` | Mac용 Apple Vision 판독 도구 |
| `research/ocr/tools/make_fixture.py` | 사진 → EXIF 회전 보정 → 두 번 판독 → 판독 기록 저장 |
| `packages/core/test/fixtures/synthetic/` | 합성 세트: 지어낸 단어로 만든 4쪽(35단어)의 판독 기록, 정답, 기준 출력 (`tools/synthetic/make_pages.py`가 생성) |
| `$SHIORI_PRIVATE_DIR/textbook/vocab_n5n3/` | (로컬 전용) 교재 5쪽 판독 기록 `pNNN.{ja,ko}.json`, 정답 59개 `ground_truth.json` |
| `$SHIORI_PRIVATE_DIR/textbook/photos/` | (로컬 전용) 원본 사진과 `pages.json`(쪽별 사진 파일, 추가 회전 각도) |

```bash
# 합성 세트 채점 (틀린 줄 상세: --verbose)
python3 research/ocr/prototype/parse_eval.py --fixtures packages/core/test/fixtures/synthetic \
  --gt packages/core/test/fixtures/synthetic/ground_truth.json

# 교재 세트 채점 (로컬 전용 자료. SHIORI_PRIVATE_DIR 기본값은 <저장소>/.private)
python3 research/ocr/prototype/parse_eval.py

# 새 사진 추가: 판독 도구 빌드(한 번) → EXIF 회전 적용 후 두 번 판독해 로컬 전용 폴더에 저장
swiftc -O research/ocr/tools/vision_ocr.swift -o /tmp/vision_ocr
python3 research/ocr/tools/make_fixture.py <사진.jpg> p070            # 옆으로 찍었으면 --rotate -90
# 그다음 로컬 전용 ground_truth.json에 정답을 추가하고 채점
```

> 교재 판독 기록과 정답 데이터에는 교재 본문이 들어 있어 저장소에 넣지 않습니다.
